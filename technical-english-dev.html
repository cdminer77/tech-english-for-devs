LESSON 01 Version Control & Git Workflow VOCABULARY
Key Terms
TermDefinitionExample
repository (repo) A storage location for your project's code and history "Clone the repo before making changes."
commit A snapshot of changes saved to the history "Write a clear commit message describing what changed."
branch An independent line of development "Create a feature branch before starting new work."
merge conflict A situation where two branches have incompatible changes "I need to resolve a merge conflict in the config file."
pull request (PR) A request to merge one branch into another, often reviewed by peers "Open a PR when your feature is ready for review."
rebase Reapply commits on top of another base branch "Rebase your branch to keep the history clean."
Common Phrases
  • "I'll push my changes shortly."– I will upload my work to the remote soon
  • "Can you review my PR?"– Please check and approve my pull request
  • "Let me cherry-pick that fix."– I'll apply only that specific commit
  • "The main branch is broken."– The primary branch has a critical error
Exercise — Fill in the Blank

Complete the sentences with the correct term: commit, branch, repository, merge conflict, pull request

  1. I created a new ________ called feature/login to work on the authentication module.
  2. After finishing the feature, I opened a ________ to get feedback from my teammates.
  3. When two developers edited the same line, a ________ occurred.
  4. Each ________ message should explain why a change was made, not just what.
  5. The project's ________ is hosted on GitHub.
1. branch  ·  2. pull request  ·  3. merge conflict  ·  4. commit  ·  5. repository
LESSON 02 Code Review Language PHRASES
Review Comment Vocabulary
TermDefinitionExample
nit / nitpick A minor, non-blocking suggestion "Nit: rename this variable for clarity."
blocking An issue that must be fixed before merging "This is blocking — it will cause a null pointer exception."
LGTM Looks Good To Me — approval shorthand "LGTM! Nice refactor."
abstraction Hiding complexity behind a simpler interface "This could benefit from a higher level of abstraction."
edge case An unusual input or condition not covered by typical logic "What happens with an empty array? That's an edge case."
Diplomatic Review Phrases
  • "Could we consider...?"– Polite suggestion without demanding change
  • "I might be wrong, but..."– Softening a critical comment
  • "This looks good overall."– Positive framing before raising issues
  • "What was the reasoning here?"– Asking for context without sounding judgmental
  • "Let's follow up offline."– Move a complex discussion out of the review thread
Exercise — Rephrase Aggressively

Rewrite these aggressive comments into professional, diplomatic ones:

  1. "This code is garbage and you clearly don't understand pointers."
  2. "Why did you do it this way?? This will never work."
  3. "Just fix the variable name, it's obvious."
1. "This approach may lead to memory issues — could we revisit the pointer management here?"
2. "I'm not sure this will handle the edge cases correctly — could you walk me through the logic?"
3. "Nit: renaming this variable to something more descriptive might improve readability."
LESSON 03 Writing Bug Reports WRITING
Bug Report Vocabulary
TermDefinitionExample
steps to reproduce A numbered list of actions to trigger the bug "Steps to reproduce: 1. Log in, 2. Click profile, 3. Save."
expected behavior What should happen according to the requirements "Expected: the form submits successfully."
actual behavior What is actually happening (the bug) "Actual: a 500 error is thrown."
severity The impact level: critical, major, minor, trivial "Severity: critical — users cannot log in."
regression A bug that was previously fixed but reappeared "This looks like a regression from the v2.1 release."
workaround A temporary solution while the real fix is pending "Workaround: clear the cache to resolve the issue temporarily."
Exercise — Write a Bug Report

Using the vocabulary above, write a short bug report (5–8 sentences) for the following scenario:

A user reports that when they upload a profile picture larger than 2MB on mobile, the page freezes and the image never saves. Smaller images work fine. The issue started after last week's update.

Title: Profile picture upload freezes on mobile for files >2MB

Severity: Major
Steps to reproduce: 1) Log in on mobile. 2) Navigate to Profile. 3) Upload an image larger than 2MB.
Expected behavior: The image uploads and the profile is updated successfully.
Actual behavior: The page freezes and the image is never saved.
Notes: Images under 2MB work correctly. This appears to be a regression introduced in last week's update. No workaround identified yet.
LESSON 04 APIs & Technical Documentation READING
API Vocabulary
TermDefinitionExample
endpoint A specific URL where an API can be accessed "The /users/{id} endpoint returns user data."
payload The data sent in a request body "Send a JSON payload with name and email."
rate limiting Restricting how many requests a client can make "The API enforces rate limiting of 100 req/min."
idempotent Calling the same endpoint multiple times produces the same result "GET requests should be idempotent."
deprecation Marking a feature as outdated and scheduled for removal "This endpoint is deprecated. Use v2 instead."
authentication token A credential used to verify identity in API calls "Include the Bearer token in the Authorization header."
Reading: Sample API Doc Snippet
// POST /api/v2/users // Creates a new user account. Requires authentication. // Rate limit: 10 requests per minute. Request Body (JSON payload): { "username": "string", // required, 3-30 chars "email": "string", // required, valid email "role": "string" // optional, default: "user" } Response 201 Created: { "id": 42, "username": "john_doe", "created_at": "2024-01-15T..." } Response 429 Too Many Requests: { "error": "Rate limit exceeded. Retry after 60s." }
Exercise — Reading Comprehension

Based on the doc snippet above, answer these questions:

  1. Which field is optional in the request payload?
  2. What HTTP status code is returned when a user is created successfully?
  3. What happens if you exceed the rate limit?
  4. What does the id: 42 in the response represent?
1. The "role" field is optional (default: "user").
2. HTTP 201 Created is returned on success.
3. You receive a 429 Too Many Requests response and must wait 60 seconds.
4. It is the unique identifier assigned to the newly created user.
LESSON 05 Agile & Scrum Terminology VOCABULARY
Agile Glossary
TermDefinitionExample
sprint A fixed time period (usually 2 weeks) to complete a set of tasks "We ship a release at the end of each sprint."
backlog The prioritized list of all pending work items "Let's groom the backlog before next sprint."
velocity The amount of work a team completes in a sprint (measured in story points) "Our team velocity is around 40 points per sprint."
retrospective (retro) A meeting to reflect on what went well and what to improve "We'll discuss the deployment issues in the retro."
blocker An obstacle preventing a task from being completed "I have a blocker — I need access to the production DB."
acceptance criteria Conditions that a feature must meet to be considered done "The acceptance criteria require mobile responsiveness."
Daily Stand-up Phrases
  • "Yesterday I worked on..."– What you completed
  • "Today I'm planning to..."– What you will do today
  • "I'm blocked by..."– What is stopping your progress
  • "I'll take that ticket."– Voluntarily picking up a task
  • "That's out of scope."– Not part of this sprint/feature
Exercise — Daily Stand-up Simulation

Write your own stand-up update (3 sentences) using the phrases above. Include: what you did yesterday, what you plan for today, and one blocker.

"Yesterday I worked on integrating the payment gateway and resolved a merge conflict on the checkout branch. Today I'm planning to write unit tests for the new endpoints and update the API docs. I'm currently blocked by missing credentials for the sandbox environment — I've pinged DevOps about it."
LESSON 06 System Design & Architecture VOCABULARY
Architecture Terms
TermDefinitionExample
scalability The ability to handle increasing load by adding resources "Horizontal scalability means adding more servers."
bottleneck A component that limits the overall system performance "The database is the bottleneck under high traffic."
latency The time delay between a request and its response "High latency is causing a poor user experience."
throughput The number of requests a system can handle per unit of time "We need to increase throughput to 10,000 req/s."
single point of failure A component whose failure would bring down the entire system "Avoid single points of failure with redundancy."
load balancer A system that distributes traffic across multiple servers "The load balancer routes requests to the least busy node."
Exercise — Match the Term

Match each scenario with the correct term: bottleneck, latency, scalability, single point of failure, load balancer

  1. Users complain that responses take 3 seconds. → ________
  2. The app runs on one server. If it crashes, everything goes down. → ________
  3. Traffic spikes on Black Friday and new servers are automatically added. → ________

  5. Requests are distributed among 5 identical backend instances. → ________
1. latency  ·  2. single point of failure  ·  3. scalability  ·  4. bottleneck  ·  5. load balancer
LESSON 07 Testing & Quality Assurance VOCABULARY
Testing Vocabulary
TermDefinitionExample
unit test Tests a single function or component in isolation "Write a unit test for the calculateTax() function."
integration test Tests how multiple components work together "The integration test checks the API and DB together."
test coverage The percentage of code exercised by tests "We require at least 80% test coverage before merging."
mock / stub A fake object simulating a dependency for testing "Mock the HTTP client to avoid real network calls in tests."
flaky test A test that sometimes passes and sometimes fails without code changes "This flaky test is caused by a timing issue."
regression test A test ensuring old features still work after new changes "Run the full regression test suite before deployment."
Exercise — True or False

Mark each statement as True (T) or False (F):

  1. A unit test checks how multiple systems interact. ___
  2. A flaky test is unreliable and can fail randomly. ___
  3. 100% test coverage guarantees bug-free code. ___
  4. A mock object replaces a real dependency during testing. ___
  5. Regression tests verify that new features work correctly. ___
1. F  ·  2. T  ·  3. F (coverage ≠ correctness)  ·  4. T  ·  5. F (they verify old features still work)
LESSON 08 DevOps, CI/CD & Deployment VOCABULARY
DevOps Vocabulary
TermDefinitionExample
pipeline An automated sequence of steps: build → test → deploy "The CI pipeline runs on every push to main."
rollback Reverting a deployment to a previous stable version "We had to rollback after the hotfix broke login."
artifact A build output (binary, Docker image, etc.) ready for deployment "The pipeline produces a Docker artifact."
environment An isolated setup: dev, staging, or production "Test in staging before promoting to production."
blue-green deployment Running two identical environments and switching traffic instantly "Blue-green deployment allows zero-downtime releases."
infrastructure as code (IaC) Managing infrastructure through code files (e.g. Terraform) "All our infra is defined as code in the repo."
Exercise — Describe a Pipeline

Using at least 4 vocabulary terms from this lesson, write a short paragraph (4–6 sentences) describing a typical CI/CD pipeline for a web application.

"When a developer pushes code to the main branch, the CI pipeline automatically runs. It builds the application and produces a Docker artifact, then runs the full test suite. If all tests pass, the artifact is promoted to the staging environment for manual verification. Once approved, a blue-green deployment is triggered on production, enabling zero downtime. If any issues arise, we can execute a rollback within minutes."
LESSON 09 Team Communication & Meetings PHRASES
Meeting Language
  • "Let's take this offline."– Discuss privately after the meeting
  • "Could you elaborate on that?"– Please explain further
  • "To summarize what we agreed on..."– Recapping decisions at the end
  • "I'll circle back on this."– I'll follow up on this later
  • "Let's park that idea for now."– Delay discussion without discarding it
  • "Can we get alignment on this?"– Do we all agree?
  • "I'll own this action item."– I'll take responsibility for this task
  • "That's a fair point."– Acknowledging someone's valid argument
Async Communication (Slack/Email)
  • "FYI — no action needed."– For Your Information only
  • "Heads up: this may affect you."– Informal warning or notice
  • "Tagging @dev for visibility."– Notifying someone to be aware
  • "ETA on this?"– When will it be done? (Estimated Time of Arrival)
  • "WDYT?"– What Do You Think?
Exercise — Translate the Jargon

Rephrase each of the following in plain, formal English:

  1. "Let's park that and circle back EOD."
  2. "Heads up — the deploy is OOO, FYI."
  3. "Can we get alignment? WDYT, @team?"
1. "Let's set that topic aside for now and revisit it at the end of the day."
2. "Please be aware that the deployment is currently out of service — this is for your information."
3. "Can we all agree on this? What does the team think?"
LESSON 10 Technical Interviews & Career PHRASES
Interview Vocabulary
TermDefinitionExample
trade-off A compromise between two competing qualities "There's a trade-off between readability and performance here."
walk me through Explain step by step "Walk me through your approach to this problem."
time complexity How runtime grows relative to input size (Big-O notation) "The time complexity of this solution is O(n log n)."
clarifying questions Questions asked to better understand the problem before solving "Can I ask a few clarifying questions before I start?"
to elaborate To give more detail or expand on an idea "I can elaborate on my design choices if needed."
Key Interview Phrases
  • "Let me think through this out loud."– Verbalizing your reasoning process
  • "My initial approach would be..."– Starting with a brute force or simple solution
  • "We could optimize this by..."– Improving your solution
  • "One edge case I should consider is..."– Showing thorough thinking
  • "The trade-off here is..."– Demonstrating architectural maturity
  • "I'm not 100% sure, but my reasoning is..."– Honest under uncertainty
Exercise — Mock Interview Answer

Answer the following interview question in 5–8 sentences using vocabulary from this lesson and previous lessons. Use at least 4 key terms or phrases.

Question: "How would you design a URL shortener like bit.ly?"

"Let me think through this out loud. Before diving in, can I ask a few clarifying questions? For instance, what's the expected throughput — thousands or millions of shortened URLs per day?

My initial approach would be a simple key-value store mapping a unique short code to the original URL. For scalability, I'd introduce a load balancer to distribute read requests across multiple database replicas, since reads will far outnumber writes.

The main trade-off here is between storage cost and collision probability in the key generation algorithm. One edge case I should consider is handling duplicate submissions of the same original URL. The time complexity of a lookup would be O(1) using a hash map. I can elaborate on the caching layer or analytics component if needed."
